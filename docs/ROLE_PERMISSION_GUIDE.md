# 系统角色与权限说明

本文说明 V2.0 五类系统角色的默认功能权限、数据范围和操作边界。系统先校验权限编码，再校验项目归属、人员范围、业务状态等数据规则；拥有菜单或权限编码不等于可以操作所有数据。一个用户可同时拥有多个角色，权限取并集，数据范围取其角色允许范围的并集。

## 角色概览

| 角色 | 编码 | 主要职责 | 项目/任务数据范围 |
| --- | --- | --- | --- |
| 超级管理员 | `super_admin` | 系统、用户、组织、角色、审计与全局业务管理 | 全部项目和任务，可执行全部项目/任务管理操作 |
| 部门主管 | `department_manager` | 全局项目任务管理、部门项目审批、评价和日程管理 | 全部项目、任务和人员日程 |
| 职能主管 | `functional_manager` | 管理链条与本人项目管理 | 本人及全部层级下属相关的项目/任务；本人负责项目可维护，其余只读 |
| 项目经理 | `project_manager` | 负责项目、成员、任务、工时和预约 | 本人负责或作为成员参与的项目及其任务；仅本人负责项目可维护 |
| 项目成员 | `project_member` | 执行任务、填报执行记录和个人日程 | 本人参与项目及其任务；项目只读，负责任务可维护备注和执行数据 |

## 统一业务规则

- 超级管理员和部门主管对项目、任务具有全局数据范围与管理权。
- 职能主管的“下属”按 `users.supervisor_id` 递归计算，不只限制两级。职能主管可查看自己及所有下属相关项目、任务和日程。
- 项目经理、职能主管仅能维护自己担任项目负责人的项目；仅作为成员参与时只读。
- 项目负责人能查看负责项目下的全部任务，即使本人不是某个任务的负责人。
- 项目成员只看到本人参与或负责任务所在的相关项目，不能看到无关项目。
- 任务项目成员可以维护任务备注，并新增、修改、删除本人的执行记录；项目成员、项目、计划日期、预计工时等核心字段由项目负责人、部门主管或超级管理员维护。
- 任务状态取最新一条未删除执行记录；删除最新记录后自动回退到上一条。父任务状态由子任务汇总。
- 全部任务完成只提示项目负责人，不自动关闭项目。项目负责人、部门主管或超级管理员确认后，项目才成为“已完成”（`completed`）。
- 项目负责人为自己预约本人负责项目的任务工时，系统自动确认；预约其他成员仍由被预约人本人确认或拒绝。
- 项目过程评价只能在项目已结束且任务已完成时提交一次，允许本项目负责人、部门主管或超级管理员操作。
- 导出继续执行相同数据范围：项目经理导出本人相关数据，职能主管导出本人及全部下属相关数据，部门主管和超级管理员可导出全部。

## 各角色说明

### 超级管理员

- 拥有系统登记的全部功能权限，并在权限依赖层直接放行。
- 可查看、创建、编辑和删除权限允许状态下的全部项目与任务，维护项目成员、确认项目完成并进行评价；项目首次审批仍必须由项目所属部门主管执行。
- 可查看和维护全部任务执行记录；为其他人员填报时，人员必须是该任务的有效负责人。
- 可管理用户、组织、角色权限、工作日历、数据导入导出和操作日志。
- 只能由初始化脚本创建；不能在用户管理中新增或移除，且系统始终保留至少一个有效超级管理员。

### 部门主管

- 查看并管理全部项目和任务，查看全部人员日程。
- 处理本人所负责部门的项目审批和项目资源申请；首页展示分配给本人的审批入口。
- 可使用已审批项目预约项目有效成员，可维护项目、成员和任务，确认项目完成并进行评价。
- 可查看用户、组织、角色、操作日志，管理工作日历及使用数据导入导出。
- 对全部任务执行记录拥有查看、代填、修改和删除权限；普通用户只能维护本人的执行记录。
- 不具备用户维护、组织维护和角色权限修改能力，除非另行调整角色权限。

### 职能主管

- 查看本人及全部层级下属相关的项目、任务和日程。
- 可以创建项目；只可维护本人负责的项目、项目成员和任务。仅作为成员或因下属关系可见的项目只读。
- 本人负责且已审批的项目可以预约有效项目成员；预约自己时自动确认。
- 可查看过程报表；只有本人是项目负责人且项目/任务已完成时才可评价。
- 可导出本人和所有下属相关数据。

### 项目经理

- 创建项目并以本人为负责人，维护基本信息与任务；工时和成员增删通过项目资源申请。
- 查看本人负责或作为成员参与的项目及其任务；参与但不负责的项目只读。
- 查看本人负责项目的全部任务，并使用已审批项目预约有效成员。
- 预约本人自动确认，预约其他成员由对方确认；额度不足或需增删成员时提交项目资源申请。
- 全部任务完成后由本人手动确认项目完成，之后方可进行一次性评价。
- 可导出本人负责、参与或承担任务的相关数据。

### 项目成员

- 是未显式选择角色时自动授予的默认角色。
- 查看本人作为成员参与的项目及其任务，但不能编辑项目或维护成员。
- 作为任务项目成员时可修改任务备注并维护本人的执行记录；不能修改任务核心计划字段或删除任务。
- 可为自己被分配的具体任务预约本人时间，预约自动确认；不能预约其他人员。
- 可管理个人时间安排，确认或拒绝发给本人的预约，并查看本人日程和通知。
- 默认没有过程报表、预约他人、导入导出和系统管理权限。

## 审批与完成规则

| 事项 | 操作人 |
| --- | --- |
| 项目首次审批 | 项目所属部门当前配置的部门主管；所有角色创建的项目都必须审批，不自动通过 |
| 追加项目工时 | 项目所属部门当前配置的部门主管；超级管理员保留应急管理权限 |
| 人力预约 | 被预约人本人；项目负责人预约自己时自动确认 |
| 项目确认完成 | 项目负责人、部门主管或超级管理员，且所有未取消任务均完成 |
| 项目评价 | 项目负责人、部门主管或超级管理员；项目已完成且尚未评价，每个项目仅一次 |

## 用户与角色约束

- 新用户必须设置部门和直属主管；最高级主管只能直接由数据库维护。
- 新用户至少有一个角色，未选择时自动授予 `project_member`。
- 超级管理员不能通过页面新增、移除、停用最后一个有效账号。
- 仍负责未结束项目的用户必须保留超级管理员、部门主管、职能主管或项目经理中的至少一个角色。
- 仍为部门负责人的用户不能移除部门主管角色。
