# 系统角色与权限说明

本文档说明项目任务与人力协同管理系统 V2.0 中五类系统角色的用途、默认功能、权限编码及业务数据范围。

适用角色：

- 超级管理员（`super_admin`）
- L3（`department_manager`）
- L4（`functional_manager`）
- 项目经理（`project_manager`）
- 项目成员（`project_member`）

> 本文档描述的是 `backend/scripts/init_data.py` 初始化的默认权限。除超级管理员外，具有“维护角色权限”权限的管理员可以在“角色权限”页面调整角色与权限的对应关系，因此运行中数据库里的实际配置可能与默认值不同。重新执行初始化脚本会把五类系统角色恢复为代码中定义的默认权限集合。

## 一、权限判定原则

系统会依次进行两层校验：

1. **功能权限校验**：判断用户角色是否包含相应权限编码，例如 `project:edit`。
2. **业务数据范围校验**：判断用户是否可以操作当前这条数据，例如是否为该项目的项目经理、是否为任务负责人、是否为被预约人本人。

因此，拥有某项功能权限不代表可以操作该模块中的全部数据。例如：

- 拥有 `project:edit`，仍然只能编辑本人负责且本人具有项目经理角色的项目。
- 拥有 `task:edit`，仍然只能修改或删除本人作为负责人的任务；创建任务还要求本人是对应项目的项目经理。
- 拥有 `execution:edit`，仍然只能填写、修改和删除本人的执行记录。
- 拥有 `schedule:edit`，仍然只能使用本人负责且已审批通过的项目预约有效项目成员。
- 拥有 `evaluation:edit`，仍然只能评价本人负责、已经结束且任务已经完成的项目任务。

一个用户可以同时拥有多个角色。多个角色的功能权限按**并集**计算，但所有业务数据范围和状态校验仍然生效。

所有已登录且状态正常的用户，无论角色如何，都可以：

- 查看首页中与本人相关的统计和待办；
- 查看、修改允许本人维护的个人资料；
- 修改本人的登录密码；
- 创建培训、会议、请假、外出等个人时间安排；
- 撤回本人的个人时间安排。

## 二、角色概览

| 角色 | 主要定位 | 默认数据范围 | 典型使用人群 |
| --- | --- | --- | --- |
| 超级管理员 | 系统初始化、基础数据、用户、组织、角色权限和运维管理 | 功能权限覆盖全部模块；业务数据仍受项目负责人、任务负责人和本人数据规则限制 | 系统管理员 |
| L3 | 部门级管理与项目追加工时审批 | 可以查看所有人的日程；只审批本人所负责部门的追加工时 | 部门主管 |
| L4 | 下属人员日程、任务执行和负载关注 | 本人、直属下属，以及直属下属的下属 | 职能主管、团队主管 |
| 项目经理 | 创建并管理本人负责的项目、任务、成员、工时和项目预约 | 本人负责的项目及其有效项目成员 | 项目负责人 |
| 项目成员 | 执行本人负责的任务，维护本人执行记录和个人日程 | 本人负责的任务、本人执行记录和本人日程 | 普通项目成员 |

## 三、各角色详细说明

### 1. 超级管理员

角色编码：`super_admin`

#### 角色用途

超级管理员负责系统级配置和基础数据治理，是系统中唯一默认拥有全部功能权限的角色。

#### 默认功能

- 查看和维护用户，启用、停用或删除符合条件的用户。
- 查看和维护部门、组织以及组织树。
- 查看角色权限，为 L3、L4、项目经理和项目成员调整权限。
- 为普通用户分配系统角色。
- 查看项目、任务、共享看板、执行记录和过程报表入口。
- 管理工作日历后台数据。
- 管理数据导入，下载业务报表。
- 查看操作日志。
- 查看和处理风险后台数据。
- 查看站内通知。

#### 特殊规则

- 超级管理员只能由项目初始化配置，不能在用户管理或角色管理中新增。
- 初始化超级管理员角色不能通过角色管理移除。
- 系统至少保留一个有效的超级管理员，最后一个有效超级管理员不能被停用或删除。
- 超级管理员始终获得系统中全部已登记权限；“角色权限”页面不允许取消其权限。
- 超级管理员并不会自动绕过业务归属规则。若要创建或维护项目、预约项目工时、评价项目任务，仍需同时具有项目经理角色并满足项目归属条件。
- 超级管理员不能修改或删除其他用户的任务执行记录。

### 2. L3

角色编码：`department_manager`

#### 角色用途

L3 是部门级管理角色，重点负责部门项目工时额度审批、全员日程查看以及管理分析。

#### 默认功能

- 查看用户、部门、组织和组织树。
- 查看角色及其权限配置，但不能修改角色权限。
- 查看项目和任务入口。
- 查看所有人员的项目预约和个人时间安排。
- 具有日程维护入口，但项目预约仍必须满足“本人同时是对应项目的项目经理”这一条件。
- 查看和填写本人的任务执行记录。
- 查看项目过程报表。
- 查看操作日志。
- 查看、处理风险后台数据。
- 管理工作日历后台数据。
- 导入业务数据、下载业务报表。
- 查看人员负载汇总后台数据。
- 查看站内通知。

#### 专属业务职责

- 只有项目所属部门中被设置为部门负责人的 L3，才能审批该部门项目的追加工时申请。
- L3 首页展示本人需要处理的追加工时审批。
- L3 如果同时具有项目经理角色，可以创建项目；该项目提交时自动通过，不产生本人审批本人的记录。
- L3 本身不拥有任务评价权限；项目评价由本项目的项目经理完成。

#### 默认不具备

- 维护用户。
- 新增、修改或删除部门和组织。
- 修改角色权限或分配用户角色。
- 评价项目任务。

### 3. L4

角色编码：`functional_manager`

#### 角色用途

L4 是下属人员管理和执行观察角色，主要关注本人管理链条中的人员日程、任务执行和负载情况。

#### 默认功能

- 查看用户、部门、组织和组织树。
- 查看项目和本人负责的任务。
- 查看本人、直属下属，以及直属下属的下属的日程。
- 查看和填写本人的任务执行记录。
- 查看本人负责项目范围内的过程报表；如果本人不是项目经理，通常没有可展示的项目范围。
- 查看、处理本人可见人员范围内的风险后台数据。
- 导入业务数据、下载业务报表。
- 查看本人可见人员范围内的负载汇总后台数据。
- 查看站内通知。

#### 默认不具备

- 维护用户、部门或组织。
- 查看或维护角色权限。
- 创建、编辑项目或维护项目成员。
- 发起项目人力预约。
- 管理工作日历。
- 查看操作日志。
- 评价项目任务。
- 审批项目追加工时。

> L4 可以创建和撤回本人的培训、会议、请假、外出等个人时间安排，但默认不能使用项目发起人力预约。

### 4. 项目经理

角色编码：`project_manager`

#### 角色用途

项目经理负责本人项目从创建、提交审批、任务拆分、成员管理、工时申请、人员预约到项目评价的完整业务流程。

#### 默认功能

- 创建项目，项目编号由系统自动生成。
- 以本人作为项目负责人提交项目审批。
- 查看和编辑本人负责的项目。
- 维护本人项目的成员。
- 为本人已审批项目创建任务并选择一个或多个任务负责人。
- 查看本人负责项目的全部任务，以及本人作为负责人的任务。
- 使用本人负责且已审批的项目预约有效项目成员，也可以预约本人。
- 修改、移动、复制、撤回或删除本人提交且状态允许的人力预约。
- 查看本人项目成员的日程；共享看板会同时展示这些人员在其他项目中的占用，以判断真实可用时间。
- 申请追加项目工时，由项目所属部门的 L3 审批。
- 查看和填写本人负责的任务执行记录。
- 查看本人负责项目的过程报表。
- 对本人负责且已经结束的项目中已完成任务进行一次性评价。
- 下载本人有权访问范围内的业务报表。
- 查看、处理本人可见范围内的风险后台数据。
- 查看人员负载汇总后台数据和站内通知。

#### 重要业务限制

- 只能创建本人作为项目负责人的项目。
- 普通项目提交后由创建人的直属主管审批；创建人没有有效直属主管时不能提交。
- 只能管理本人负责的项目，不能编辑其他项目经理的项目。
- 只能预约本人项目中的有效成员，且项目必须已审批通过、未完成、未取消。
- 预约必须关联同一项目中的有效任务，并受项目工时额度、工作日历、工作时段和时间冲突校验限制。
- 人力预约由被预约人本人确认或拒绝；对方确认前，提交人可以撤回。
- `task:edit` 不代表可以修改所有项目任务。已有任务只能由该任务负责人修改或删除。
- 评价只能执行一次；评价完成后，相关项目执行记录不再允许变更。

#### 默认不具备

- 用户、组织和角色权限管理。
- 数据导入。
- 工作日历维护。
- 操作日志查看。

### 5. 项目成员

角色编码：`project_member`

#### 角色用途

项目成员是普通用户的默认角色，负责执行本人承担的任务、填写实际执行情况和维护个人日程。

#### 默认功能

- 查看首页中与本人相关的项目、任务、延期、预约和通知信息。
- 查看本人作为负责人的任务。
- 修改或删除本人作为负责人的任务，但仍受任务状态、项目状态、子任务、预约和执行记录等规则限制。
- 查看、填写、修改和删除本人的任务执行记录。
- 查看本人的日程。
- 创建和撤回本人的培训、会议、请假、外出等个人时间安排。
- 确认或拒绝发给本人的人力预约。
- 查看站内通知。
- 查看与本人范围相关的风险后台数据。

#### 重要业务限制

- 默认没有项目管理权，不能创建项目、维护项目成员或申请追加工时。
- 虽然默认包含 `project:view`，当前普通项目列表仍按“本人负责的项目”限制；项目成员角色本身不会获得全部项目列表。
- 只能处理本人的执行记录，不能替其他成员填写、修改或删除执行记录。
- 没有 `schedule:edit`，不能使用项目发起人力预约。
- 没有项目过程报表和任务评价权限。

| 报表 | `process_report:view` | 查看项目过程和负载报表 | 项目过程报表按本人负责项目限制；负载按日程可见人员范围限制 |

| 风险 | `risk:handle` | 处理和关闭风险 | 当前 UI 隐藏，后台逻辑保留 |
| 通知 | `notification:view` | 查看通知、未读数、标记已读 | 只能处理本人的站内通知 |
| 数据交换 | `import:manage` | 下载导入模板、执行导入和查看导入记录 | 用户导入与角色分配另有超级管理员校验 |
| 数据交换 | `export:download` | 导出预约、执行和过程报表 | 导出数据继续遵循当前用户的数据范围 |
| 分析 | `analytics:view` | 查看人员负载汇总接口 | 当前 UI 隐藏，按日程可见人员范围过滤 |

## 六、审批职责与角色的关系

系统中“审批人”不仅由角色决定，还由业务关系决定：

| 审批事项 | 审批人规则 | 角色要求 |
| --- | --- | --- |
| 项目首次审批 | 项目创建人的有效直属主管 | 接口按指定审批人校验，不要求固定为 L3/L4；创建人同时为 L3 或超级管理员时自动通过 |
| 追加项目工时 | 项目所属部门当前设置的负责人 | 必须具有 L3 角色，且必须属于该部门 |
| 人力预约 | 被预约人本人 | 不由项目经理、L3、L4或超级管理员代审 |
| 项目任务评价 | 本项目的项目经理 | 必须具有项目经理角色；项目已结束、任务已完成且未评价 |

## 七、角色分配和维护约束

- 新用户至少拥有一个系统角色；如果未指定，系统自动授予项目成员角色。
- 一个用户可以同时是 L3、L4、项目经理或项目成员，权限按并集生效。
- 仍负责未结束项目的用户不能移除项目经理角色。
- 仍被设置为部门负责人的用户不能移除 L3 角色。
- 超级管理员只能通过初始化脚本配置，不能通过普通用户新增、导入或角色分配产生。
- 禁用或删除用户后，即使仍存在角色关系，也不能登录和使用系统。
- 调整角色权限会影响拥有该角色的所有用户，应先确认业务影响再保存。

## 八、推荐角色组合

| 使用场景 | 推荐角色 |
| --- | --- |
| 仅执行任务、填报工时、维护个人日程 | 项目成员 |
| 创建和管理项目、预约项目成员、评价项目 | 项目经理，可同时保留项目成员 |
| 管理团队下属并查看两级下属日程 | L4，可按实际工作同时授予项目经理 |
| 负责部门追加工时审批并查看全员日程 | L3，可按实际工作同时授予项目经理 |
| 系统初始化、用户组织权限和运维管理 | 超级管理员；如需实际管理项目，再额外授予项目经理 |
