# 项目计划日期调整（2026-10-09）

## 使用方式

1. 打开项目管理 → 项目详情 → **项目资源申请**。
2. 填写“新计划开始日期”“新计划结束日期”；只需修改哪个就填写哪个，留空表示不变。可以提前或推迟日期，不要求项目先逾期。
3. 按需填写追加工时、增删成员和申请原因。检查二次确认中的原日期 → 新日期后提交。
4. 部门主管在首页待处理事项或项目的资源申请列表查看日期、人员、工时变更，批准后生效；此前项目仍按原计划执行。
5. 尚未审批时，申请人可以撤回后重新申请；驳回或撤回均不改变现有计划。

## 适用范围与校验

- 已审批、未完成的项目可以申请。未开始、进行中、已逾期均不影响入口；已完成项目不开放新的资源申请。
- 已审批项目普通编辑中的两个计划日期只读，后端也禁止直接变更，避免绕过审批。名称、描述、备注等基本信息仍按原权限编辑。
- 正在审批的立项申请不能编辑；草稿仍可编辑，驳回后的立项申请仍可修改后重新提交部门主管。这次不改变上述流程。
- 审批权限仍限项目所属部门当前指定的部门主管。超级管理员没有额外代批权限。
- 新结束日期不得早于新开始日期。只填一个日期时，与当前未修改的另一个日期一起检查。
- 新周期必须覆盖所有未删除任务的计划日期，以及有效预约（包含未过期的待确认/改期预约及已确认/执行中/已完成预约）。不自动移动、缩短或删除任务与预约。
- 提交与批准均执行检查。等待审批期间若新增任务/预约不再符合新周期，会阻止批准并给出原因；应先处理冲突，或驳回/撤回后重新申请。
- 一项目同时仍只允许一个待审批资源申请。新日期申请保留完整原计划快照，审批时发现计划已变化会拒绝批准，避免覆盖其他变更。
- 首页待办、资源申请列表、通知及日志展示修改前后起止日期。日期批准后写入项目同一数据源，不伪造实际执行日期、不修改任务进度。

## 工时规则

- **延长结束日期**：保留原规则，追加工时必须为正数且以 0.5h 为单位。默认值 = 延长部分工作日 × 变更后有效项目人数 × 8h，包含项目经理并去重，遵循工作日历的节假日/调休配置。
- 如同时将开始日期推迟到原结束日之后，默认值仅计算新开始至新结束，不计中间不属于新周期的空档。
- **只改开始日期或提前结束日期**：可以仅申请日期变更，追加工时为 0；需要额外预算时手工填写。提前开始增加的天数不自动估算，缩短周期不自动减少已有预算。
- 手动输入优先于自动估算；取消延长结束日期时清除旧的自动追加工时，但保留主动手填值。清空两个日期且没有其他变更，或只填与原计划相同的日期，不能提交空申请。
- 自动估算失败时不会用缺失结果提交，可以重新选择日期或手动填写合法工时。

## 数据库与部署（由维护者执行）

新增迁移 `20261009_0021`，上游为 `20261008_0020`。只为 `project_resource_requests` 增加两个可空 DATE 列：

- `original_planned_start`：申请时原开始日期。
- `requested_planned_start`：申请的新开始日期。

已有结束日期字段保留。历史申请新增字段保持 NULL，不伪造快照；旧的结束日期延期申请继续兼容，审批时仍校验最新业务边界。

## 供维护者自行验收

1. 未逾期、已审批项目可申请新的起止日期；待审批时项目日期不变。
2. 普通编辑两日期只读；直接调用编辑 API 修改任一日期也被拒绝，但基本信息仍可保存。
3. 只改开始日期、缩短结束日期可填 0h；延长结束日期填 0h 被拒绝，合法半小时工时可提交。
4. 同时修改两日期时按新的组合校验；只改一个时按当前另一个日期校验，禁止倒置。
5. 新周期排除任务/有效预约时不能提交；申请后新建冲突任务/预约，批准时同样阻止。
6. 部门主管首页待办和资源列表显示原/新起止日期，批准后项目页、甘特图读取新计划；任务与预约不自动移动。
7. 驳回、撤回不修改计划与工时；重复批准被拒绝；非部门指定主管不能批准。
8. 旧的结束日期申请仍可展示和审批；新申请迁移字段已存在时可重试迁移。
9. 日期切换、清空、重新打开表单时，自动工时不沿用旧结果；手填值不被估算覆盖。
