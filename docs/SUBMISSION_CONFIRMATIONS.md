# 业务提交二次确认

更新日期：2026-10-09。

## 使用方式

填写表单后点击提交/保存，系统先执行原有前端校验，然后显示确认框。核对操作对象、日期、工时或影响后，再点击“确认提交”“确认批准”等按钮，才向后端提交。

- 点击“取消，暂不操作”、关闭图标或按 Esc：不发送该操作的写入请求，主表单仍保留，可以继续修改。
- 点击弹窗外侧不会自动确认或关闭。
- 驳回原因、备注等独立输入弹窗中的“下一步”只完成输入，之后仍需确认操作；若在最终确认时取消，不保存该原因或备注，下次操作需要重新填写。
- 删除、撤回等已有确认流程使用统一弹窗，不在旧弹窗后再追加相同确认。
- 同一次“保存项目并提交审批”仅在开始前确认一次。10 月 9 日起新建项目和必传报告通过同一请求保存，文件失败则回滚创建；保存成功后提交审批仍是独立步骤，该步骤失败不回滚已保存的草稿。已有草稿的编辑、报告替换仍按原分步流程处理。
- 批量预约只确认一次，显示人员、时间及总工时；拖动改期展示原时段与新时段。
- 确认框按纯文本渲染，不展示密码。长名单或说明可以在弹窗内滚动，操作按钮保留在内容下方。

## 覆盖范围

| 模块 | 需要确认的操作 |
| --- | --- |
| 首页待办抽屉 | 项目、父任务、资源、加班审批的批准/驳回；预约接受/拒绝 |
| 项目管理 | 新建/编辑/保存草稿（含所选立项报告）、提交审批、批准、驳回、删除、确认完成 |
| 项目详情 | 提交资源申请（追加工时、延期、增减成员）、撤回/批准/驳回资源申请、确认项目完成 |
| 任务管理及项目详情任务页 | 新增父任务并提交审批、新增子任务、编辑任务/备注、删除、批准/驳回、重新提交审批 |
| 任务共享看板 | 新建/修改预约、批量预约、拖动改期、接受/拒绝、撤回/取消预约；保存/撤回个人安排 |
| 任务执行 | 新建/编辑/删除执行记录；提交、批准、驳回、撤回加班申请 |
| 项目过程报表 | 提交项目评价 |
| 用户管理 | 新增/编辑、启用/禁用、删除用户；随用户表单提交的角色及密码设置 |
| 组织管理 | 新增/编辑/删除部门和组织 |
| 角色权限 | 保存角色权限 |
| 右上角个人菜单 | 修改个人资料、修改密码、主动退出登录 |
| 数据导入导出 | 执行 Excel 导入（说明成功行会入库，失败行不会回滚成功行） |
| 通知中心 | 全部标为已读、删除通知、清空已读通知 |
| 隐藏的工作日历页面 | 保存/删除自定义日历规则；不恢复页面入口 |
| 隐藏的风险中心页面 | 手动风险扫描、保存风险处理结果；不恢复页面入口 |

不增加确认的操作：登录、导航、打开/关闭表单、查看详情、搜索筛选、分页、展开折叠、选择附件、下载模板/附件/报表、阅读单条通知，以及自动刷新和后台定时任务。选择附件本身不上传，上传随项目保存一起确认。未被页面调用的历史 API 方法不添加弹窗逻辑。

## 实现位置与边界

- `frontend/src/utils/confirm.ts`：`confirmAction` 统一确认文案、按钮、取消处理和弹窗互斥；`requestActionReason` 处理必填原因输入。
- `frontend/src/styles/index.css`：确认框多行文本、自适应宽度与长内容滚动样式。
- 各页面及业务组件：在原有校验后、第一条业务写入请求前调用确认；需要输入原因的决策在输入后确认。
- 确认放在用户操作层，不放进 Axios 请求拦截器，避免一个流程的多个 HTTP 请求反复弹窗。
- 保留原有权限、审批人规则和后端业务校验。弹窗只是防误操作，不是后端权限防线、事务回滚或接口幂等机制。
- 同一时刻只展示一个本工具创建的确认/原因弹窗；保存按钮使用页面加载状态防止误点。服务器端仍负责状态、权限及并发冲突判断。
- 本次无需新依赖、新接口、新数据库迁移。若同时部署此前的项目附件或父任务审批功能，请仍按对应文档完成原有升级步骤。

## 维护者手工验收清单（未执行）

1. 新建项目，填写有效内容并选择附件：点击保存/提交先出现一次确认。取消时无项目创建、附件上传或审批提交请求，主表单和所选附件保留；确认后按原流程提交。
2. 新建父任务和子任务：无效表单先显示校验信息；有效表单先确认，父任务确认后进入审批，子任务按原规则保存。项目详情中的任务页也应如此。
3. 从首页和模块页面分别批准/驳回项目、父任务、资源、加班申请。原因输入完成不应直接驳回，最终确认取消时业务状态不变。
4. 看板分别验证单人预约、本人预约、批量预约、接受、拒绝、撤回与取消。点击原按钮均应先确认；本人预约仍按原规则自动通过，但不能绕过提交前确认。
5. 拖动预约：确认框显示新旧时间；取消时预约位置和后端时间不变，确认时才提交改期。
6. 验证保存及撤回个人安排、执行记录保存及删除、提交项目评价，均先确认。确认失败应显示原有后端错误，不伪报成功。
7. 验证用户、组织、角色权限、个人资料及密码的保存，取消时不更新数据，密码不出现在确认文本中。
8. 验证批量导入、通知全部已读/删除/清空的确认；查询、下载、查看详情和阅读单条通知不额外打断。
9. 验证点击取消、关闭图标和 Esc 均不会产生业务写入；反复点击原按钮不应叠出多个确认框。取消后保存按钮应恢复可用。
10. 使用较长项目名、多人名单及含 `<`、`>` 的说明，确认内容应可读、可滚动且按文本显示，不执行 HTML。

交付仅做文件编辑和源码静态核对，未安装依赖、运行测试/构建、执行迁移、访问数据库或启动服务。以上清单留给维护者部署后自行执行。
