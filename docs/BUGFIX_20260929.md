## 默认工时口径

`计划工时 = 起止日期之间的工作日数（含首尾） × 成员人数 × 8h`

- 项目与任务调用同一个只读后端接口，使用现有工作日历中的节假日与调休工作日；未配置覆盖记录的日期沿用周一至周五工作日规则。**需要维护者保证工作日历数据准确**，本次不联网导入节假日。
- 项目人数为“项目经理 + 选中的初始项目成员”，按用户 ID 去重，因为经理原本就会自动加入项目。表单明确显示“含项目经理”。
- 任务人数为当前选中的任务项目成员，按 ID 去重；子任务仍只能选择父任务已有成员。
- 自动模式下改日期或人数会重新计算。手动调整后保留手动值，旁边仍展示计算参考值，可点“使用默认值”恢复。重新打开新建表单恢复自动模式；编辑已有项目/任务不会重新计算覆盖历史计划。
- 旧异步响应不得覆盖新日期的计算结果；计算失败会提示，可重试或手动填写，不使用假数据替代。
- 所选周期没有工作日时默认值为 0，提示调整日期或手填正数；不悄悄改成 0.5h。任务半小时规则、根任务总工时不超过项目额度、同级子任务总工时不超过父任务等校验继续生效。

## 项目延期流程

1. 项目经理进入已逾期项目详情，点击“项目资源申请”。
2. 在“项目延期至（可选）”选择新的计划结束日期，并填写原因；可以同时申请工时和成员变更，也可以只申请延期。
3. 新日期必须晚于原结束日期，且不早于提交当天的北京时间日期。已有待审批资源申请时，沿用一次仅一单的规则。
4. 申请期间原项目周期保持不变；首页待办、资源申请列表和站内/已配置邮件通知显示延期内容。
5. 由项目所属部门当前设置的部门主管审批；超级管理员保留既有资源审批管理权限。项目负责人身份本身不能审批资源申请。
6. 批准时重新检查日期、原计划是否变化和项目是否仍开放；已过时的申请需驳回重提。批准后才更新项目结束日期，写入前后变更日志；驳回不改日期或额度。
7. 延期只改项目计划结束日期，不自动修改任务计划、预约、实际日期或工时。项目有效状态按既有动态规则重新显示；已有逾期任务需按实际安排维护，不能因项目延期而被假定完成。

已审批项目不能通过基本信息接口直接延长结束日期，普通描述、备注等编辑仍走原流程。未审批草稿/驳回项目仍可修改计划日期。

## 执行记录校验与权限

- 普通项目成员仍只看自己的执行记录；项目负责人额外看自己负责项目的全部记录；超级管理员/部门主管保留既有全量权限。
- “只看本人”开关可收窄范围，项目/任务/执行人筛选始终与服务端权限范围取交集，不能靠传参查看无关记录。
- 列表与单条详情都检查权限；项目负责人查看他人记录时不展示编辑/删除按钮，后端也拒绝越权写入。
- 已完成的新记录必须明确传 `actual_hours`；更新时检查合并后的记录，不允许将已完成记录的工时清空。仅更新其他字段可以保留已有合法工时。
- 正常执行的进行中记录仍可留空按工作日容量计算；手工工时不能超过日期容量。加班继续受批准工时和既有凭证约束。
- API 拒绝 `4.3`、`4.25`、零、负数或非有限工时。`0.5`、`4`、`4.5` 等在容量允许时合法。
- 历史错误工时不自动取整，避免篡改真实记录；如编辑旧记录时遇到非半小时数值，需要人工核实后修正。
