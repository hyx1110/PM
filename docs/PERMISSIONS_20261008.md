# 2026-10-08/09 日程与多角色权限调整

## 规则

### 项目经理查看日程

2026-10-09 按最新需求，改为**全系统角色包含“项目成员”的有效用户**，替代此前按项目成员关系确定人员范围的规则。

- 范围为本人，加上 `user_roles` / `roles` 中具有 `project_member` 角色且账号启用、未删除的用户；与所属部门、项目是否存在、项目审批/完成状态无关。
- 尚未加入任何项目、已退出所有项目的用户，只要仍有该角色，就可查看其日程（包括请假、会议等个人安排）；兼任项目经理或其他角色不会排除。
- 只有项目参与/负责人关系、没有项目成员系统角色的其他用户，不再因此自动进入该范围；本人及其他角色原有的可见范围仍保留。
- 为用户授予/移除项目成员角色后，下一次日程请求重新读取数据库角色关系，无需重新初始化数据。刷新页面可同步更新人员选项与预约/个人安排。
- 若兼任职能主管，额外并入其下属日程范围；部门主管/超级管理员已有的全员日程范围不变。
- 看板人员选项、按项目筛选选项、预约列表/详情和个人安排共用后端人员权限函数。已有工号排序与“我的日程”置顶保持不变。
- 用户主动选择项目、部门/组织/人员筛选时，仍在权限范围内继续缩小结果；要看到未参与项目的成员，请先清空项目筛选。
- 仍保留待确认预约隐私：其他项目经理提交、尚未被预约人确认的记录，不向无关项目经理公开；确认成功的工作安排可以查看。
- **可查看不等于可操作**：只凭项目经理角色，仍只能为本人负责且已通过审批的项目预约有效项目成员，并校验具体任务成员。项目管理、任务管理和首页项目范围不因此改为全量。

### 超级管理员与兼任

- 新增/编辑用户的“系统角色”仍是多选，可选超级管理员、部门主管、职能主管、项目经理、项目成员。
- 超级管理员可以和任意其他角色兼任，不再限制只能在初始化时创建超级管理员。
- 只有现有超级管理员可以授予或移除超级管理员角色。普通角色即使被赋予用户/角色维护菜单权限，也不能直接通过接口给自己提升该角色。
- 未选择角色仍默认项目成员；新增用户仍需部门、直属主管及两次一致的密码，本次不放开最高级主管的档案创建规则。
- 不允许移除、停用或删除最后一个有效超级管理员。已设为部门负责人的用户仍须保留部门主管角色，未结束项目负责人仍须保留可管理项目的角色。
- Excel 批量导入不自动授予超级管理员：请由现有超级管理员在用户管理中逐一设置。

### 项目审批

初次项目审批和项目资源申请审批（追加工时、成员变化、延期）统一满足：

1. 用户具有 `department_manager`（部门主管）角色。
2. 是“组织管理”中项目所属部门当前指定的负责人。
3. 账号、部门有效，且用户部门与项目所属部门一致。
4. 申请处于允许审批的状态。

| 用户身份 | 能否审批项目及资源申请 |
| --- | --- |
| 仅超级管理员 | 不能 |
| 超级管理员 + 项目经理 | 不能 |
| 部门主管，但不是项目所属部门指定负责人 | 不能 |
| 部门主管，并且是项目所属部门指定负责人 | 可以 |
| 超级管理员 + 部门主管，且是项目所属部门指定负责人 | 可以，按部门主管身份 |

批准和驳回都执行同一业务校验。角色菜单权限的超级管理员特例不会跳过此校验；首页只返回本人能处理的部门审批待办，项目列表与资源申请页也按相同规则展示按钮。

用户预约确认、任务执行和加班审批没有改为部门主管统一审批，仍遵循各自原有规则。

- 同步部署前后端；被调整角色的用户刷新或重新登录；自己修改自己的角色时，用户管理会立即重新获取个人权限。
- 新建仅具备项目成员角色、从未加入任何项目的有效用户，设置请假或会议；项目经理在无项目筛选的看板及人员选项中应可看到其姓名和个人安排，空日程也应保留人员行。
- 为一个用户同时授予项目成员和其他角色，验证其日程仍可见；移除项目成员角色后刷新，若不存在本人/下属等其他可见关系，应不再出现在项目经理看板。
- 对只有项目参与关系、没有项目成员系统角色的其他用户，验证不会因加入项目而自动公开日程；停用、删除账号也不应因该角色进入人员列表。
- 用项目经理查看具有项目成员角色的其他项目人员的已确认预约；不属于本人负责项目或具体任务成员时，预约接口仍应拒绝。
- 对另一个项目成员发起未确认预约后，用第三个项目经理查看，确认仍不可见。
- 创建“超级管理员 + 项目经理 + 项目成员”账号，确认能正常保存并显示多个角色。
- 用仅超级管理员账号检查首页、项目列表、资源申请页无部门审批按钮；直接请求批准/驳回接口也应拒绝。
- 给账号兼任部门主管，并在组织管理设置为所属部门负责人，确认仅该部门的审批进入首页；其他部门不能代批。
- 验证不能移除、停用或删除最后一个有效超级管理员。
