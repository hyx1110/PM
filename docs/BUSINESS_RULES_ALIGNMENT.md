# 当前业务规则对齐

本文是当前代码采用的最终业务口径。角色是系统功能角色，不再区分人事职级或角色来源。

## 用户与组织

- 用户保留数字主键；`employee_no` 同时是唯一登录账号。
- 业务字段为员工号、姓名、邮箱、部门、组织、直属主管和系统角色。
- 新增/导入用户必须设置部门和直属主管；最高级主管由维护者直接写入数据库。
- 系统角色固定为超级管理员、L3、L4、项目经理、项目成员。未选择角色时默认项目成员。
- 直属主管关系禁止循环；删除主管前必须先处理全部下属及其管理关系。

## 项目、任务和权限范围

- 超级管理员和 L3 查看、管理全部项目和任务。
- L4 查看本人及所有层级下属相关的项目和任务；仅本人负责项目可维护。
- 项目经理查看本人负责或参与的项目；本人负责项目可编辑、维护成员和任务，参与项目只读。
- 项目成员查看本人参与或承担任务的相关项目，不能维护项目。
- 项目负责人可以查看本人项目的全部任务。任务负责人可以修改备注和维护本人执行记录；任务核心计划字段与删除操作由项目负责人、L3 或超管控制。
- 人员筛选统一支持姓名/工号，组织筛选统一支持部门/组织名称。

## 项目审批、工时与完成

```text
创建项目
  -> 普通创建人保存草稿并提交
  -> 创建人的有效直属主管审批
  -> 已审批项目可维护成员、任务和预约
  -> 额度不足时申请追加工时
  -> L3/超级管理员审批追加工时
  -> 全部任务完成后提示项目负责人
  -> 项目负责人/L3/超级管理员手动确认项目完成
```

- 项目经理、L4、L3、超管可创建项目；非全局角色必须以本人为项目负责人。
- L3/超管创建项目时自动通过，避免自己审批自己。
- 项目编号自动生成，创建时必须设置部门、计划日期、总工时及至少一名初始成员。
- 全部任务完成不会自动把项目设为完成，也不会阻止项目负责人补充任务；只有手动确认后关闭。

## 执行与状态

- 同一任务可有多条执行记录。
- 叶子任务状态取最新一条未删除记录，排序依据为 `created_at DESC, id DESC`。
- 删除最新记录后回退到上一条；没有记录时为未开始。
- 父任务由未取消子任务汇总。部分子任务完成视为已开始。
- 项目运行态由任务汇总，但完成态只能由手动确认产生。
- 实际工时可由工作日容量自动计算，也可手工填写；手工值必须大于 0 且不超过所选日期工作日容量。

## 日程与预约

- 每个用户可创建并撤回本人的培训、会议、休假、外出、出差或其他安排。
- 有效个人安排阻止任何人在重叠时段预约该用户；已有有效预约也阻止创建重叠个人安排。
- 超管/L3 看全部人员日程；L4 看本人及全部下属；项目经理看本人项目成员；普通成员看本人。
- 项目负责人使用本人负责且已审批项目预约有效成员；L3/超管可全局预约管理。
- 项目负责人预约自己承担的本人项目工时时自动确认；预约他人时由被预约人确认或拒绝，确认前提交人可撤回。
- 预约只允许工作日 `08:30-12:00` 或 `13:00-17:30`，按 30 分钟粒度，法定节假日不可预约。

## 首页、报表和导出

- 首页“我的任务”仅显示本人负责任务。
- 近 14 天计划工时按北京时间今天及前 13 天的已确认、进行中、已完成项目预约汇总；本月按自然月汇总。
- 首页项目、任务、工时和延期统计使用当前账号可见项目范围。
- 项目过程报表使用同一项目范围。项目和任务完成后，项目负责人、L3 或超管可评价一次。
- 导出范围与页面权限一致，并支持项目、姓名/工号、部门/组织筛选。
