# 业务规则对齐说明（2026-09-15）

本文归档本轮确认后的最终业务口径。它覆盖旧文档中与项目审批人、角色来源、人员主数据维护方式不一致的描述。

## 1. 五类系统角色保留

系统继续保留五类独立的功能角色：

| 角色代码 | 页面名称 | 主要用途 |
|---|---|---|
| `super_admin` | 超级管理员 | 用户、权限、配置和全局数据 |
| `department_manager` | L3 | 部门资源与项目管理、追加工时审批 |
| `functional_manager` | L4 | 职能范围内的项目、任务和资源管理 |
| `project_manager` | 项目经理 | 创建项目、任务、成员和人力预约 |
| `project_member` | 项目成员 | 自己的任务、日程、预约和执行记录 |

鉴权依据始终是“系统角色 + 组织关系 + 项目关系”。HR 职级本身不直接参与权限判断。

## 2. HR 职级只是角色来源

`employee_profiles.hr_management_level` 是归一化的人事管理职级：

- `department_manager` 自动授予系统角色 `department_manager`（L3）；
- `management_manager` 自动授予系统角色 `functional_manager`（L4）；
- `employee` 不自动授予 L3/L4。

`user_roles.is_manual` 和 `user_roles.is_hr_auto` 分别记录人工来源和 HR 自动来源。两种来源可以同时存在，撤销 HR 来源不会误删仍由人工授予的角色。

新增用户即使没有勾选角色，也会默认获得 `project_member`，从而保证每个有效用户至少有一个系统角色。

## 3. HRDB 主数据边界

当前仍使用 MySQL 测试数据，不连接正式 HRDB。`employee_profiles`、`departments`、`organizations` 均增加 `data_source=local|hrdb`：

- `local` 数据可在当前测试系统维护；
- `hrdb` 数据只允许由未来的同步程序写入；
- HRDB 用户的姓名、联系方式、部门、组织、岗位、人事职级和直属主管在业务 API 中只读；
- HRDB 部门和组织不能在业务页面编辑或删除；
- 账号状态、密码以及人工系统角色仍由本系统维护。

正式接入时，员工、部门、组织、岗位、直属主管和在职状态以 HRDB 为准。本版本只完成数据结构和只读边界，不包含正式连接器和真实数据导入。

## 4. 项目审批最终规则

本轮最终选择“创建人的直属主管”审批，不再使用“项目所属部门 L3”审批项目创建：

```text
项目经理创建草稿
  -> 提交审批
  -> 创建人的有效直属主管审批
  -> 通过 / 驳回
```

- 项目经理可以保存草稿；没有有效直属主管时不能提交。
- L3 或超级管理员创建项目时系统立即自动通过，不产生自己审批自己的记录。
- 直属主管即使只有项目成员角色，也能通过首页待办和项目列表完成被指定项目的审批。
- 项目所属部门 L3 继续负责“追加项目工时”审批，这是另一条独立流程。
- 已完成或已取消项目不能新增任务、成员预约等业务数据；项目状态只能按规定方向流转，完成和取消为终态。

## 5. 项目成员、任务和日程

- 创建项目时必须按“部门 -> 组织 -> 启用人员”指定至少一名初始成员；项目经理自动作为固定成员写入成员表且不能移除，项目获批后可继续维护普通成员。
- 任务负责人只能是项目经理或当前有效项目成员。
- 任务状态统一为未开始、进行中、已完成、已暂停、已取消；延期是根据截止时间计算出的展示状态。
- 普通项目成员通过“我的任务”查看自己负责的任务，列表包含项目、项目经理、计划时间、预计工时、已预约工时和状态。
- 任务预计工时不得小于该任务待确认、已确认、变更待确认、进行中及已完成预约占用的有效工时，避免待确认预约通过后反向突破任务工时。
- 项目预约必须绑定项目、任务、人员和时间段，只能预约工作日的 `08:30-12:00` 或 `13:00-17:30`。
- 驾驶舱及负载报表的可用工时与预约使用同一工作日历，法定节假日不计容量，调休工作日计入容量。
- 培训、会议、休假、外出、出差和其他个人安排都会阻止重叠预约；每个用户只能设置和撤回自己的个人安排。
- 新预约由被预约人本人确认或拒绝，提交人在对方确认前可以撤回。
- 项目经理只能预约本人负责项目中的当前有效成员；L3/L4 可预约 `supervisor_id` 指向自己的直属下属，但被预约人仍必须是所选项目的当前有效成员。

## 6. 可见范围与首页待办

- 普通成员：可查看自己参与的项目，但任务、日程、预约、执行记录和风险只限本人；
- 项目经理：日程看板显示本人及自己负责项目的当前有效成员；查看其中某个人员时，可看到该人员跨项目的时间占用，以判断真实可用时间；
- L3：日程看板显示全部有效人员；其他项目、任务、执行、风险和报表范围仍按既有项目管理规则处理；
- L4：日程看板显示本人及 `supervisor_id` 指向自己的直属下属；
- 超级管理员：全局。

共享看板第一行固定为“我的日程”。首页按身份展示今日/临期任务、待本人确认预约、项目异常或待直属主管审批项目，并提供快捷入口。

## 7. 历史数据保留

- 项目和任务使用软删除；
- 执行记录和通知使用软删除；
- 预约的删除操作转换为取消状态；
- 项目成员移除使用 `left_at` 保留历史；
- 已拒绝、已撤回、已取消记录不再占用日历或项目额度，但历史记录保留。
- 软删除的项目、任务和执行记录不进入正常业务列表或经营统计，审计历史仍可追溯。

对应数据库增量迁移为 `20260914_0007_business_rules_alignment.py` 和 `20260915_0008_project_manager_membership.py`；后者只为历史项目回填项目经理成员关系。
