# 业务规则对齐说明（2026-09-16）

本文归档本轮确认后的最终业务口径。它覆盖旧文档中与项目审批人、角色来源、人员主数据维护方式不一致的描述。

## 1. 五类系统角色保留

系统继续保留五类独立的功能角色：

| 角色代码 | 页面名称 | 主要用途 |
|---|---|---|
| `super_admin` | 超级管理员 | 用户、权限、配置和全局数据 |
| `department_manager` | L3 | 全员日程查看、部门追加工时审批 |
| `functional_manager` | L4 | 本人及两级下属日程查看 |
| `project_manager` | 项目经理 | 创建项目、任务、成员和人力预约 |
| `project_member` | 项目成员 | 自己的任务、日程、预约和执行记录 |

鉴权依据始终是“系统角色 + 组织关系 + 项目关系”。

## 2. 用户模型已简化

- 用户唯一登录账号为 `users.employee_no`，内部关联继续使用数字主键 `users.id`；
- 用户业务字段仅保留姓名、邮箱、部门、组织和直属主管；
- 系统角色通过 `user_roles` 直接分配，不再区分人工或 HR 自动来源；
- 未显式分配角色的用户默认获得 `project_member`；
- 手机号、兼容用户名、岗位、人员档案和人事职级已从当前模型移除。

## 3. 数据维护边界

当前系统只使用 MySQL，用户信息由项目管理系统直接维护，不包含 HRDB 人员档案、职级映射、岗位同步或真实人员导入逻辑。部门和组织表自身已有的 `data_source` 字段属于组织主数据范围，不会自动产生用户角色。

## 4. 项目审批最终规则

本轮最终选择“创建人的直属主管”审批，不再使用“项目所属部门 L3”审批项目创建：

```text
项目经理创建草稿
  -> 提交审批
  -> 创建人的有效直属主管审批
  -> 通过 / 驳回
```

- 项目经理可以保存草稿；没有有效直属主管时不能提交。
- 只有项目经理可创建项目；创建人同时具有 L3 或超级管理员角色时系统立即自动通过，不产生自己审批自己的记录。
- 直属主管即使只有项目成员角色，也能通过首页待办和项目列表完成被指定项目的审批。
- 项目所属部门 L3 继续负责“追加项目工时”审批，这是另一条独立流程。
- 已完成或已取消项目不能新增任务、成员预约等业务数据；项目状态只能按规定方向流转，完成和取消为终态。

## 5. 项目成员、任务和日程

- 创建项目时必须按“部门 -> 组织 -> 启用人员”指定至少一名初始成员；组织未分配但部门有效的用户也可被选择。项目经理自动作为固定成员写入成员表且不能移除，项目获批后可继续维护普通成员。L3/L4 只有同时具备项目经理角色并负责该项目时，才获得项目维护能力。
- 任务负责人支持多选，且都必须是当前有效项目成员；任务列表只展示本人作为负责人的任务，只有任务负责人可以编辑。
- 任务状态统一为未开始、进行中、已完成、已暂停、已取消；延期是根据截止时间计算出的展示状态。
- 普通项目成员通过“我的任务”查看自己负责的任务，列表包含项目、项目经理、计划时间、预计工时、已预约工时和状态。
- 任务预计工时不得小于该任务待确认、已确认、变更待确认、进行中及已完成预约占用的有效工时，避免待确认预约通过后反向突破任务工时。
- 项目预约必须绑定项目、任务、人员和时间段，只能预约工作日的 `08:30-12:00` 或 `13:00-17:30`。
- 驾驶舱及负载报表的可用工时与预约使用同一工作日历，法定节假日不计容量，调休工作日计入容量。
- 培训、会议、休假、外出、出差和其他个人安排都会阻止重叠预约；每个用户只能设置和撤回自己的个人安排。
- 新预约由被预约人本人确认或拒绝，提交人在对方确认前可以撤回。
- 只有项目经理可使用本人负责且已审批的项目预约当前有效项目成员；L3/L4 的行政角色只扩展日程查看范围，不自动获得其他项目的预约权。

## 6. 可见范围与首页待办

- 普通成员：任务列表只显示本人负责的任务，项目列表不展示非本人负责项目；日程只显示本人，执行记录只能维护本人；
- 项目经理：日程看板显示本人及自己负责项目的当前有效成员；查看其中某个人员时，可看到该人员跨项目的时间占用，以判断真实可用时间；
- L3：日程看板显示全部有效人员，并在首页审批所属部门的追加工时；
- L4：日程看板显示本人、`supervisor_id` 直属下属及第二级下属；
- 超级管理员：项目和任务仍遵守项目经理/任务负责人的业务数据范围；为系统运维与排障保留全员日程查看范围，但不能绕过项目经理关系发起预约。

共享看板筛选项目、姓名、工号、部门或组织后，不匹配人员整行移除。首页直接展示我的任务、待本人确认预约、待直属主管审批项目和 L3 追加工时审批。

## 7. 历史数据保留

- 项目和任务使用软删除；
- 执行记录和通知使用软删除；
- 预约的删除操作转换为取消状态；
- 项目成员移除使用 `left_at` 保留历史；
- 已拒绝、已撤回、已取消记录不再占用日历或项目额度，但历史记录保留。
- 软删除的项目、任务和执行记录不进入正常业务列表或经营统计，审计历史仍可追溯。

对应数据库增量迁移包括 `20260914_0007_business_rules_alignment.py`、`20260915_0008_project_manager_membership.py` 和 `20260916_0010_task_multi_assignees.py`。
