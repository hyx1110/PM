# 0930 资源申请、通知与操作日志修复

本次仅编辑源码、回归用例源码及文档。未安装依赖、连接业务数据库、执行迁移、运行测试或构建、启动服务，也未发送邮件或进行浏览器实测。

## 1. 项目延期工时自动计算且必填

- 入口：逾期项目详情 → 项目资源申请 → 选择新的结束日期。
- 默认追加工时 = **原结束日期次日至新结束日期（含）的工作日数 × 变更后的有效项目成员人数 × 8h**。复用现有 `/work-calendar/planned-hours` 接口，遵循工作日历与调休配置。
- 人数为现有有效成员加本次新增、减本次移除，含项目经理且去重。默认只计算新增延期区间，不重新累计原项目周期预算；成员调整不会另外推算原周期工时，仍可根据实际需要手动调整。
- 允许手动修改；手动输入后，不因日期/成员改变而静默覆盖，提示已保留手动值并提供“使用默认值”。自动计算进行中、失败或缺失有效结果时，不允许把之前遗留的默认值直接提交；可明确手动填写后提交。
- 延期时字段显示必填星号，前端与后端均要求正数；资源申请工时为 0.5h 的整数倍。只有成员变更、不延期时仍可填 0h。新增区间没有工作日时，明确提示调整日期或按需要手动填写正数工时。
- 申请不会立即改变项目日期/预算，仍需部门主管批准。旧的 0h 延期申请不能直接批准，申请人应撤回后补齐工时重提，或由主管驳回；已批准历史记录不改写。

## 2. 资源申请撤回

- 入口：项目详情 → 资源申请 → 本人待审批记录的“撤回”。
- 新接口：`POST /api/v1/projects/{project_id}/resource-requests/{request_id}/withdraw`。
- 后端要求 `project:edit` 且申请人本人、状态 `pending`；不能撤回他人申请，也不能撤回已批准、已驳回或已撤回记录。
- 撤回与批准/驳回统一按 **项目 → 申请** 加行锁并刷新 ORM 实体；一个操作已生效后，另一个会收到明确业务错误，不重复应用资源变化。
- 撤回只改变申请为 `withdrawn`、更新修改时间并记日志；不增加或扣减预算、不增删成员、不改项目日期、不伪造审批人。申请人可以重新提交，原申请保留用于审计。
- 当前部门主管收到撤回通知。下一次查询首页待办/项目待审批数时，已撤回申请不再计入；已经打开的旧审批窗口无法绕过后端状态校验。

## 3. 审批展示成员明细

- 资源申请列表与待审批列表批量解析 `add_members/remove_members`，提供姓名和工号；原始 `add_member_ids/remove_member_ids` 保留用于业务操作。
- 项目详情列表、审批确认提示、首页待办内容及其详情都展示“新增/移除 N 人：姓名（工号）”，不再只有人数。
- 新生成的资源申请通知也带具体成员名单。退出项目、被停用的员工仍可解析历史资料；若资料已物理删除，明确显示“原成员资料已不存在”，不悄悄减少申请人数。

## 4. 预约通知业务化描述

- 公共通知入口统一添加被预约人姓名/工号、项目名、任务名、完整北京时间时段。
- 明确区分待本人确认、已确认、已拒绝、已撤回、因时段冲突自动关闭、超时未确认自动取消。保留原申请/拒绝/撤回说明，仅替换技术性“预约 #数字 / 排期 #数字”表达，不篡改说明中的其他数字。
- 新通知内容在事件发生时保存，后续项目/用户改名或预约改期不会改变这条通知的原始描述。新站内通知与已启用的邮件投递共用该保存内容。
- 历史通知的 GET 列表根据它关联的预约补全**当前可解析的姓名、项目、任务**，但不把预约当前时段冒充成历史事件时段，不根据预约当前状态重写历史处理结果。资料已删除时显示无法还原提示。该读取不写库、不改已读状态、不重新排队发送邮件；已经发出的历史邮件无法被修改。

## 5. 操作日志

- 摘要改为“操作人 + 动作 + 业务对象名称 + 具体变化”，关联人员、项目、任务、部门、组织、角色和权限 ID 在摘要中转换为名称；预约状态以“待本人确认 → 已确认”等中文表达。
- 新日志在原 JSON 字段保存 `_display_labels` 名称快照；以后改名时优先使用快照。旧日志没有名称快照时按当前档案批量补全，不改写历史记录。资料确实缺失时明确提示，不编造名称。
- 日志列表隐藏“原因”列，模块名称改为中文。详情先显示可读摘要，再显示原始修改前/后数据；操作说明、内部 ID、记录 ID 继续保留供审计，未删除数据库字段。
- 后台仍沿用现有按天目录、按小时文件的日志方式，文件中的摘要也使用可读描述；没有新增日志定时任务。

## 留给维护者的验收清单（未执行）

1. 延期日期更改、跨法定节假日/调休、增加/移除成员时，核对默认追加工时公式；手动值不会被覆盖，默认值按钮可恢复计算结果。
2. 延期工时留空、0、负数、0.3、4.3：前端或 API 均拒绝；4.5 可提交；只变更成员、不延期可为 0。断网估算失败后不能提交旧默认值。
3. 本人待审批申请可以撤回，工时/日期/成员保持不变，可重提；其他人、已批准/驳回/撤回的申请均不允许再次撤回。
4. 两个会话同时批准和撤回同一申请：只能有一方成功，另一方得到已处理提示；预算不会重复追加。
5. 从项目详情与主管首页分别查看增删多人申请，人数与全部姓名/工号一致；包含已停用、退出项目人员时不漏人。
6. 创建、改期、确认、拒绝、撤回、竞争邀请关闭、超时取消预约：新通知明确指向人员/项目/任务和事件结果；旧通知的内容可以读懂且未读数不因展示补全变化。
7. 查看用户、组织、项目、任务、成员调整、预约、执行等日志：摘要无单独的 `#85` 对象表达；原因列消失，原因与真实 ID 仍可在详情/后台中追溯。
8. 生成新通知/日志后改名或改期：原通知内容和新日志名称快照保持事件时信息；缺失的旧历史资料显示明确提示，不能出现推测的历史时段。
