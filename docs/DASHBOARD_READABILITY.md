# 首页办公屏幕适配说明

## 目标与范围

以公司 1920×1080 显示器的日常阅读为目标，降低信息密度、保留可读字号。2026-10-10 将首页由四行精简为两排，待处理事项改为点击右侧抽屉；复用已有本人今日日程和真实业务聚合数据。左侧导航、顶栏和其他业务页面不变。滚动样式按最新要求恢复横向条、继续隐藏纵向条，保留滚轮操作。

### 首页顶部精简

- 首页模块也精简固定说明：“项目进度”标题不再显示项目总数和模块介绍，“我的今日日程”不再显示底部操作说明；待办与关注抽屉移除重复介绍。统计卡、图例、日期、真实日程及错误提醒保留。
- 首页隐藏“工作台 / 首页”面包屑，移除“管理驾驶舱”、用户名引导语及右侧数据范围/更新时间说明，统计卡片直接成为首屏内容。
- 顶栏继续保留“项目任务与人力协同管理系统”、通知、账号和角色菜单，不另增提示语或空白占位。
- 仅首页路由设置 `meta.hideBreadcrumb`，其余页面导航保持不变。只删除展示和对应的闲置样式/导入，数据接口、数据权限、待办处理、甘特图及其他卡片逻辑不变。

## 新的模块顺序

1. **顶部概览**：待处理事项、进行中项目、任务完成率、需要关注，顺序不变。任务完成率仅统计任务成员包含当前登录用户的有效任务，卡片展示“已完成数 / 总数 个本人任务”；同一项目内与本人无关的任务不计入，无本人任务时为 0%。顶部待办卡片的总数只展示一次：有待办时数字使用淡红底，并显示“有事项待处理 · 点击查看”。悬停显示统计说明；点击“待处理事项”从右侧打开列表，不再定位到下方，也不自动悬浮展开列表。
2. **日程与项目**：宽屏与顶部统计卡共用四列等宽网格和 **20px** 列间距。我的今日日程占第一列，与第一张统计卡左右边缘对齐；项目进度跨第 2–4 列，与第二张卡左边缘、第四张卡右边缘对齐。移除原日程最低 300px 限制，避免撑偏网格。并排时两卡等高，随内容共同伸缩，最低 **320px**、最高 **640px**；超过后各自内容区滚动。甘特图保留逐项目/全部展开收起、固定表头和左侧名称/负责人，不因布局减少项目。

移除首页常驻的待处理面板、关注列表、项目健康度、计划与实际、工时趋势。顶部“需要关注”仍可点击，在右侧抽屉查看异常和明细；不让保留的统计卡片成为无效按钮。移除的是首页展示，不删除相关业务数据或后台统计。

### 待处理事项抽屉

- 点击顶部卡片打开宽度最高 640px 的右侧抽屉，不跳转页面。分类继续为“全部 / 审批与预约 / 我的任务”，只显示当前账号原有权限范围内的摘要。
- 点击审批或预约条目，继续打开原有详情抽屉；确认/驳回仍使用原 API、权限与二次确认。成功后关闭该详情、保留待办列表，并刷新顶部计数、待办内容和今日日程。
- 点击我的任务打开任务详情；关闭详情后仍可继续浏览待办列表。详情抽屉挂载到 `body`，避免在外层抽屉中被裁剪。
- 提供手动刷新、失败提示和无待办空状态。列表可滚轮浏览，页头、分类和底部提示保留；不显示纵向拖动条，内容横向溢出时保留横向拖动条。
- 日程详情中的未确认预约提供“查看待处理事项”入口，并更新原来“左侧面板”的过时指引。

卡片留白和间距以 20–24px 为主，模块标题 20px、主要正文 14–15px、辅助文字 12–13px。增加行高和按钮点击区域，删除重复的装饰性英文小标题；首页不再单独显示页面主标题。

## 展开与数据边界

- 首页项目范围统一按“本人 + `users.supervisor_id` 递归关联的全部层级下属”计算，再取这些人负责、作为有效成员参与或承担任务的项目并去重。无下属时只取本人相关项目，部门归属相同本身不意味着下属关系。
- 所有系统角色（包括部门主管和超级管理员）均使用上述首页范围，多角色不会自动扩大为全系统项目；无关联时显示空状态。项目/任务管理等其他页面的原有权限不变，首页待办仍遵守原审批人和被预约人规则。
- 顶部任务完成率在首页项目范围内进一步限定为当前用户本人的任务成员关系，与“我的任务”共用筛选；分子、分母均排除已删除、待审批及已驳回任务，多人任务计一次。统计全量符合条件任务，不受个人任务摘要 40 条上限影响；项目进度和风险指标仍按原项目范围汇总。
- 甘特图首次打开显示项目摘要，用户展开后直接显示接口返回的重点任务；审批刷新时保留已有展开/折叠选择。全部展开仅针对当前展示的项目，不代表下载全系统项目。
- 甘特图返回上述范围内的全部已审批项目，取消原先最多 5 个项目的查询上限，不按角色设显示数量上限；模块标题不再附带项目总数，实际项目行仍完整展示，空结果不退回全量项目。默认折叠，展开后才渲染任务行，避免项目增多时在隐藏区提前创建所有任务节点。
- 每个项目仍预览最多 6 条重点任务，项目进度和完成数量按该项目全部有效任务计算，不按预览条数计算；展开后明确提示预览数量并提供项目详情入口。这是任务摘要规则，不是项目数量上限。项目实际日期和工时继续来自真实执行记录，执行聚合查询限定在首页相关项目内。
- 保留计划/实际工期双条、今天竖线、状态、负责人、真实任务进度；悬停查看日期，点击任务打开详情抽屉。今天及本月判断沿用北京时间工具。
- `DashboardPendingPanel` 改为嵌入 `DashboardPendingDrawer`，不再常驻首页；展示当前接口返回的未完成任务和待办摘要，底部标明已展示数 / 待办总数。接口原有摘要上限仍保留（个人任务最多 40 条、本人待确认预约最多 100 条等），条目不足总数时明确提示去对应业务模块查看，不伪称加载全量待办。
- 顶部“需要关注”与抽屉均按同一个 `risk_alerts` 数组逐项计数；抽屉标注“共 N 项关注事项”，直接展示全部返回条目并允许滚动。同一项目不同异常分别计数，历史记录与即时检测的重复延期提醒合并。取消关注列表及风险数据源的 8/12 条截断，补齐项目自身延期；超时待办仍取现有待办摘要，所有用户可见范围保持原规则。旧工时对比预览仍保留前 12 条。
- 不增加 mock 数据，不调整工时、任务、项目状态、权限或审批规则；无新增依赖、数据库字段或本次新增迁移。前序项目延期改动的迁移要求仍以对应说明为准。

## 我的今日日程：真实数据及时间规则

- 复用 `/api/v1/dashboard/workbench` 的 `my_day: { date, items }`，按当前登录用户 ID 查询；管理员/主管在这张卡片中也只看自己的日程，不能混入下属或其他人的安排。
- 取北京时间当天 00:00 至次日 00:00 之间有交集的记录，包含已确认/进行中/已结束的项目预约，以及未撤回的培训、会议、休假、外出、出差等个人安排。尚未到结束时间的待确认/改期待确认预约也单独显示，但标注“待确认，尚未占用时间”。
- 排除已取消、已拒绝、草稿、已过期未确认的预约及已撤回的个人安排；已确定且今天早些时候结束的时段仍保留，便于回顾一天。并发邀请逐条展示，不合并覆盖，不将多个待确认邀请累计成已占用工时。
- 日程为从早到晚的竖向时间线，显示开始/结束、来源、项目/安排名称、时段状态；当前时段弱蓝色强调、待确认使用虚线卡片。点击打开只读详情抽屉，显示完整日期和备注。
- 跨天安排在今日时间线中裁剪为 00:00/24:00，接口和详情保留原始起止时间。显式将无时区的后端时间按北京时间解释，不用浏览器所在地时区替代。
- 加班不进入此日程；时段已结束不代表任务已完成，日程时长也不是实际执行工时。数据查询只读，不自动确认、取消或修改预约。
- 前端每分钟更新时段提示；北京时间跨日或跨日后回到标签页时刷新一次首页，失败不循环重试。日程右上角可手动刷新；刷新失败或仍显示前一天数据时给出提示，不默默标为今天的新数据。审批/预约处理后的首页刷新也同步更新此日程。

## 窄窗口适配

- 浏览器视口宽度大于 1500px：上下共用四列等宽网格和 20px 列间距，日程占一列、项目跨三列。不要改成独立的 `1fr 3fr` 两列，因为两排扣除的间距数量不同，仍会错位。
- 视口宽度不大于 1500px：顶部四卡变为两列，下方日程和项目各占一列，列边界和间距同步；加载占位也使用相同参数。
- 视口宽度不大于 1440px：上下排间距缩小为 20px，保留组件原有的较小内边距和字号；不再为日程设置独立的 300px 最小宽度。
- 视口宽度不大于 1280px：顶部仍为两列，下方日程和项目各跨两列、单独占整行，避免缩小字号挤压内容。各卡片的高度限制仍保留。
- 甘特表格保留 940px 的最小内容宽度，容器不足时局部横向滚动，不挤压日期字号；在 Chrome / Edge 中可直接拖动底部横向滚动条，也可用触控板横向手势或浏览器支持的 Shift + 鼠标滚轮。纵向条继续隐藏，上下滚轮浏览不变。
- 判断依据是浏览器 CSS 视口而非显示器标称分辨率；系统显示缩放、浏览器缩放和窗口大小都会影响断点。全系统现有 1180px 最小页面宽度未改变，本次不是移动端整体适配。

## 留给维护者自行查看

以下是手工查看清单，并非已执行的测试结果。本次只编辑源码并静态阅读，未安装、启动、构建、测试或浏览器截图验证。

1. 在公司 1920×1080 屏幕、浏览器正常缩放下，查看顶部字号、甘特图日期和任务名称；再分别按公司实际使用的系统/浏览器缩放查看布局。
2. 首页只出现顶部四卡和第二排“我的今日日程 / 项目进度”。逐个/全部展开收起项目时，两卡同高、可缩小至 320px、最高 640px；超出后内部滚轮浏览，表头仍可见，第 6 个及以后的项目不得消失。
3. 展开多个项目，审批一条待办刷新首页：仍在返回范围内的项目保留展开状态。
4. 点击待处理卡片打开右侧列表，悬停不打开列表；核对三个分类、关闭/刷新、空状态和失败提示。继续打开详情并确认/驳回，列表与计数更新，原二次确认仍在。项目、资源、父任务、加班审批及预约确认均使用原权限。
5. 在任务名很长、多负责人、无数据、待办数量较多时检查换行、列表滚动和信息提示；待办卡片不得再出现重复总数徽标，空卡片上下边缘保持对齐。
6. 宽屏下核对日程边缘与第一张统计卡对齐、项目进度边缘与后三张统计卡整体对齐。缩窄窗口按 1500px / 1280px 断点核对两列/整行布局及加载占位；图表只在各自容器内横向滚动，字号不随窗口变小。
7. 直接打开首页或从其他页面返回：首页首屏从统计卡片开始，不再出现重复标题、引导语或范围说明；切换到项目/任务等页面仍显示原面包屑，顶栏账号与通知入口保留。
8. 分别用项目成员、项目经理、职能主管、部门主管和超级管理员登录：只出现本人/下属相关已审批项目，不显示无关项目；管理员没有任何关系时应显示空状态。
9. 构造下属的下属及更深层级，确认关联项目都纳入且不重复；同部门但不在主管链上的无关人员项目不纳入。
10. 给账号关联 7 个或更多已审批项目，确认第 6 个及以后均出现在甘特图，不能因为隐藏标题旁的数量而减少项目行；审批刷新后保留有效项目的展开状态。
11. 为本人安排今天的预约、会议、培训、跨天休假以及重叠的未确认邀请：时间线均逐条展示、顺序正确，跨天详情仍是原日期；取消、拒绝、撤回后的记录刷新后消失。主管账号的“我的今日日程”不得混入下属日程。
12. 模拟北京时间跨日或网络失败后刷新：不显示错误的“今天”空数据，提供明确提示与重试；待办确认成功后日程中的邀请状态同步刷新。顶部“需要关注”点击仍有可查看的抽屉，日程未确认详情可直达待办。此次仅调整前端，已有首页接口保持不变，无需新迁移。
