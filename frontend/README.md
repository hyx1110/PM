# V2.0 前端

前端使用 Vue 3 Composition API、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus、Tailwind CSS 和 Day.js。V2.0 不新增图表依赖，驾驶舱和分析页使用原生 CSS 图形，避免扩大前端依赖面。

## V2 页面

- `views/dashboard`：管理驾驶舱，以及被预约人本人的预约待办和快捷确认/拒绝。
- `views/schedule`：日/周/月共享看板、个人培训/会议/休假安排与撤回、人员全部安排抽屉、时间点刻度、非工作时间及法定节假日配色、拖动、批量排期、复制上周。
- `views/schedule/WorkCalendarView.vue`：L3 法定节假日和调休工作日维护。
- `views/workload`：人员负载与项目占比。
- `views/risk`：风险筛选、扫描和处理。
- `views/notification`：站内通知与多渠道偏好。
- `views/data-exchange`：Excel 模板、导入任务、错误明细和报表导出。
- `views/analytics`：经营分析报表。
- `views/user`：员工号账号、组织关系、人工系统角色与正式人员档案双页签维护，并展示 L3/L4 授权来源。
- `views/role`：继续维护超级管理员、L3、L4、项目经理、项目成员的系统功能权限，并提示其与正式人事职级是不同概念。

## 维护者执行

```powershell
npm install
npm run dev
```

维护者自行检查和构建：

```powershell
npm run type-check
npm run build
```

本次 V2.0 文件交付没有运行上述命令。

## 交互约定

- 登录表单统一填写员工号。新增用户时员工号只能由英文、数字和英文符号组成；姓名可使用任意语言，编辑时员工号不可修改。
- 用户编辑框把“账号与组织”和“人员档案与职级”分开。人工系统角色可独立勾选；正式 `department_manager`/`management_manager` 职级会分别提示自动授予 L3/L4。
- 用户列表分别显示人工、职级自动或两者并存的角色来源，避免把人事职级误认为系统角色。
- 项目经理创建项目时必须填写所属部门与总工时，提交后等待 L3 审批；项目详情展示额度并提供追加工时申请/审批。
- 所有登录用户都可从共享看板右上角进入“我的时间安排”，设置自己的培训、会议、休假或其他占用；只能管理和撤回本人创建的个人安排。
- 生效中的个人安排会按类型着色显示在日/周/月视图；保存前若与项目预约或其他个人安排重叠，会展示结构化冲突明细。撤回后对应时段重新开放。
- 新建预约按钮直接提交，不保存草稿；只有被预约人本人看到“本人同意/本人拒绝”，原提交人在确认前看到“撤回预约”。
- 预约表单按上午/下午提供半小时选项并自动计算工时，节假日与普通周末在日期控件中禁选，服务端仍会二次校验。
- 驾驶舱通过 `/schedules/my-pending` 只读取当前用户本人需要处理的预约；首页按钮调用本人确认/拒绝接口，不授予代批权限。
- 看板时间文字位于格线边界，每格代表相邻时间点之间的 30 分钟；工作日的 `08:00-08:30`、`12:00-13:00`、`17:30-18:00` 和普通周末使用灰色禁用背景，工作日历中的法定节假日整天使用红色系背景，调休工作日恢复正常工作时段颜色。
- 看板人员列是可点击入口；点击后使用独立的无日期、无项目过滤查询，在抽屉中按时间倒序分页展示当前权限范围内该人员的全部项目预约。
- 共享看板拖动排期时提交当前 `version`；服务端发现并发变更返回 `40903`，前端提示刷新。
- 排期冲突沿用 `40901` 和结构化 `conflicts`，冲突项通过 `conflict_type` 区分项目预约与个人安排；批量排期保持原子冲突检查，复制周排期则跳过冲突项并返回明细。
- 文件下载使用 Blob；上传只接受 `.xlsx`。
- 通知角标在主框架加载时读取未读数，完整阅读和偏好设置在通知中心完成。
- 通知角标和通知中心使用同一个 Pinia 状态；单条已读、全部已读或删除未读通知后会先即时更新，再向服务端复核未读总数。
