# 项目任务与人力协同管理系统 V2.0

面向企业内部项目、任务、人员、排期和执行协同的前后端分离系统。当前 V2.0 界面聚焦首页待办、项目、任务、共享日程、执行、过程评价与通知；人员负载、风险中心和工作日历保留后台能力但不展示页面，经营分析报表已从产品入口和 API 中移除。

本次交付只创建、编辑和归档源码与文档，没有安装依赖、执行迁移、生成运行时 Excel、运行测试、构建前端或启动任何服务。README 中的命令均留给项目维护者自行执行。

## V2.0 功能范围

V1.0 原有能力全部保留：

- JWT 登录、员工号账号、用户/部门/L1-L4 组织、五类默认系统角色和项目数据权限。
- 项目、项目成员、多级任务、项目成员、周期、项目工时额度和动态逾期状态。
- 日/周人员共享看板，预约直接提交、本人确认/拒绝、提交人撤回、变更重确认和冲突检测。
- 执行记录、实际工时、达成评价、项目过程报表和操作日志。

V2.0 新增：

- 管理驾驶舱：首页直接汇总“我的任务”、项目完成/延期情况、本人待确认预约、部门主管审批待办、近 14 天计划工时和本月计划工时；统计口径随当前账号数据范围变化。
- 人员负载与风险扫描：后台聚合、扫描和处理代码继续保留，当前 UI 不展示。
- Excel 数据交换：用户、项目、任务标准模板和逐行导入；排期、执行、项目过程报表导出；导入任务与错误明细留档。
- 通知中心：新排期、排期变更、确认/拒绝、临期任务和风险通知；入口统一放在页面右上角，左侧不再重复展示。
- 增强共享看板：日/周/月视图、拖动改期、乐观版本控制、多人员批量排期和冲突检测。
- Redis + Celery 后台任务：周期风险扫描、临期提醒生成、多渠道通知投递。
- 安全删除：用户、项目、任务、执行记录和通知使用软删除；预约删除转为取消状态，审批和工时历史继续保留。
- 项目审批与资源额度：项目经理、职能主管、部门主管和超级管理员可创建项目；非全局角色仅维护本人负责的项目，所有项目都提交给项目所属部门的部门主管审批，不再自动通过；追加工时、添加成员和移除成员统一通过“项目资源申请”审批。
- 预约工作日历：仅允许工作日的 `08:30-12:00` 或 `13:00-17:30`，按 30 分钟自动计算工时；法定节假日不可预约。
- 负载口径统一：日负载和周/月可用工时读取同一工作日历，法定节假日不计容量，调休工作日计入容量。
- 角色展示名称统一为“部门主管”和“职能主管”，角色代码仍使用 `department_manager` / `functional_manager` 以兼容已有权限数据。
- 驾驶舱预约待办：仅向被预约人展示本人待确认记录，并支持在首页直接同意或填写原因拒绝。
- 看板时间与颜色优化：时间显示为边界刻度点；正常工作时间保持白色，工作日上班前、午休、下班后及普通周末使用灰色禁用背景，法定节假日使用独立红色系，调休工作日按工作日显示。
- 人员全部安排入口：点击共享看板左侧人员姓名，可查看该人员不受当前日期和项目筛选限制的全部可见项目预约，支持状态筛选、分页和单条详情。
- 个人时间安排：每个登录用户都可为自己设置培训、会议、休假、外出、出差或其他安排，并可主动撤回；生效中的个人安排会显示在共享看板，并阻止项目经理、部门主管、职能主管等任何人员重复预约该时段。
- 项目成员与日程权限：创建项目时必须先指定至少一名成员；项目负责人只可使用本人负责且已审批的项目预约有效成员；部门主管可查看所有人的日程，职能主管可查看本人及全部层级下属，项目经理可查看本人项目成员。
- 通知未读状态同步：右上角角标与通知中心共享同一状态，单条已读、全部已读和删除未读通知后都会立即刷新未读数量。
- 简化用户模型：`employee_no` 同时作为唯一登录账号，保留内部数字主键；用户业务字段只保留姓名、邮箱、部门、组织、直属主管和系统角色。
- 五类系统角色直接授权：超级管理员、部门主管、职能主管、项目经理、项目成员及其权限全部保留，不再建立人事职级或角色来源模型。
- 默认成员角色：新增用户若未选择任何系统角色，自动授予 `project_member`，确保每个有效用户至少一个角色。
- 任务与待办：“我的任务”直接显示在首页；任务支持选择多名项目成员。项目负责人维护核心任务字段，任务项目成员维护备注和本人执行数据，新增任务不再设置优先级和任务类型。
- 项目与任务范围：超级管理员/部门主管查看并管理全部；职能主管查看本人及全部下属相关数据；项目经理和项目成员查看本人负责或参与的数据，仅项目负责人可维护项目。两者支持合并的部门/组织、姓名/工号筛选，项目编号由系统自动生成。
- 筛选与人员排序：项目、任务和共享看板将部门、组织、人员合并为“部门 → 多级组织 → 人员”可搜索单选级联框；项目页人员节点代表项目经理，任务页代表任务项目成员，看板代表日程人员。用户及成员列表按工号升序，共享看板将当前登录人的“我的日程”固定在首行，其余人员按工号升序。
- 项目进度状态：与任务统一显示未开始、进行中、已完成、已逾期；前三项为数据库状态，已逾期根据计划结束日期动态计算。迁移 `20260922_0015` 会物理删除历史已取消项目及其任务、预约、执行、评价、风险、资源申请、成员关系和关联通知，操作日志继续保留。
- 部门主管首页审批：项目与项目资源申请进入项目所属部门主管的首页待办，可在首页批准或驳回。
- 登录与用户校验：登录失败区分“用户名或密码错误”和“账号已禁用”；新增用户必须选择部门，初始密码及确认密码均为必填。
- 时间口径：MySQL 会话、应用业务时间和日志时间统一采用北京时间（Asia/Shanghai）。
- 状态自动联动：最新一条未删除执行记录驱动任务状态，删除最新记录后回退到上一条；父任务自动汇总。项目运行态随任务联动，但全部任务完成不会自动关闭项目，须由项目负责人、部门主管或超级管理员手动确认完成。
- 实际日期自动联动：项目实际开始/结束日期由有效执行记录自动汇总，项目表单和更新接口不会手工覆盖。
- 日期与工时校验：任务计划日期、执行实际日期统一按天保存，所有开始/结束字段均校验先后顺序；实际工时留空时按工作日容量自动计算，手工填写不得超过容量。
- 评价结果锁定：本项目负责人、部门主管或超级管理员只能在项目和任务完成后提交一次评价；项目进入评价阶段后不再允许新增、修改或删除执行记录。
- 数据范围收敛：项目、任务、报表和导出统一按全局角色、管理链条、项目负责人/成员及任务项目成员关系过滤；普通用户不再看到无关数据。
- 个人中心：右上角用户菜单支持修改姓名、邮箱和登录密码。
- 组织与审计：组织树直接展示组织下用户及未分配组织人员；操作日志展示字段级变更，FastAPI 与 Celery 进程日志均写入 `logs/YYYY-MM-DD/app-HH.log`。

V2.0 不包含 MES/EES/YES 实时集成、正式 HRDB 连接器和真实数据导入、AI 自动排期、AI 风险预测、移动 App、通用可配置审批引擎和 Kubernetes。当前项目与项目资源申请都使用“项目所属部门主管”固定审批流。

## 项目审批与人力预约规则

1. 项目经理、职能主管、部门主管或超级管理员可以创建项目；非全局角色必须以本人为项目负责人。项目必须填写所属部门、大于 0 的总工时及至少一名初始成员，且所属部门必须配置有效部门主管；编号自动生成，项目负责人自动加入成员表且不能移除。
2. 项目创建后先保存为 `draft`，提交后统一进入 `pending`，审批人固定为项目所属部门当前配置的部门主管；任何创建者角色都不会自动通过。
3. 初始成员在项目创建表单中按“部门 → 组织 → 启用人员”选择并随项目一并保存；未分配组织但已设置部门的用户也可以选择。项目获批后的成员增删与追加工时统一通过项目资源申请，批准前不生效；成员不再维护投入比例。
4. 任务支持任意层级。子任务项目成员必须来自父任务；同级子任务预计工时合计不得超过父任务工时，顶级任务预计工时合计不得超过项目工时。任务只有未开始、进行中、已完成和动态计算的已逾期四种展示状态。
5. 预约只能选择任务已指定的项目成员。待确认提案只对申请人与被预约人可见，不占用人员时段或项目/任务额度；同一时段可存在多个提案，被预约人确认其中一条后，其他重叠提案自动关闭并通知申请人。
6. 普通任务项目成员可为自己被分配的任务预约本人时间，不能预约其他人员；本人预约自动确认。填写执行记录前，执行人必须已有与该任务及实际日期重叠的已确认预约；执行状态只保留进行中和已完成。
7. 一次预约必须在同一工作日、同一上午或下午时段内，以 30 分钟为粒度，只允许 `08:30-12:00` 或 `13:00-17:30`。法定节假日不可预约，调休工作日按工作日处理。
8. 每个用户可在“任务共享看板 → 我的时间安排”中设置自己的培训、会议、休假、外出、出差或其他安排。生效个人安排会阻止任何重叠预约，本人撤回后时段重新开放。点击本人空白时间格也会直接进入个人时间设置。
9. 共享看板按权限和筛选条件生成整行：超级管理员/部门主管看到全部有效用户；职能主管看到本人及全部层级下属；项目经理看到本人项目成员；普通成员看到本人。其他领导或项目经理只能看到已确认/进行中/已完成的安排，看不到与自己无关的待确认或失败提案。

迁移内置数据依据[国务院办公厅关于 2026 年部分节假日安排的通知](https://big5.www.gov.cn/gate/big5/www.gov.cn/gongbao/2025/issue_12406/202511/content_7048922.html)。工作日历页面当前隐藏，后续年度数据由维护者通过后台管理接口或数据库迁移维护。

## 全新本地部署

### 1. 环境文件

```powershell
Copy-Item .env.example .env
Copy-Item backend/.env.example backend/.env
Copy-Item frontend/.env.example frontend/.env
```

至少修改 `SECRET_KEY`、数据库密码、`INITIAL_ADMIN_PASSWORD` 和 `IMPORT_DEFAULT_PASSWORD`。为兼容既有部署，环境变量仍名为 `INITIAL_ADMIN_USERNAME`，但它现在表示初始管理员的员工号及登录账号。`INITIAL_ADMIN_PASSWORD` 只在初始化脚本首次创建管理员时生效，不会在服务重启或再次初始化时覆盖已有账号密码；已有管理员应通过用户管理重置密码。外部通知未配置时，站内通知仍可独立使用。

### 2. 后端、任务队列与数据库

维护者自行准备 MySQL 8 和 Redis 7，然后在 `backend` 目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
python -m scripts.init_data
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

另开终端启动 Celery Worker 和 Beat：

```powershell
celery -A app.tasks.celery_app:celery_app worker --loglevel=INFO
celery -A app.tasks.celery_app:celery_app beat --loglevel=INFO
```

### 3. 前端

在 `frontend` 目录执行：

```powershell
npm install
npm run dev
```

### 4. Docker Compose

根目录执行：

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

Compose 包含 `mysql`、一次性 `migrate`、`redis`、`backend`、`worker`、`beat` 和 `frontend`。`migrate` 成功后其余后端服务才会启动；默认入口为 `http://localhost`。

## Excel 规则

- 仅接受 `.xlsx`，上传大小受 `IMPORT_MAX_MB` 控制。
- 必须使用系统下载的对应模板，工作表和标题行不能修改。
- 日期必须是 Excel 日期/时间单元格或受支持的标准文本日期；工时必须是数字，不要附加单位。
- 用户、项目、任务分别通过员工号、项目编号及其关联编码解析关系。只有超级管理员可以导入用户和分配系统角色，用户导入必须填写有效部门编码；导入项目时模板中的项目编号值会被忽略并由系统自动生成，项目模板必须填写成员员工号且只能由模板中的项目经理本人导入；任务模板不提供优先级和初始状态，支持用逗号填写多名负责人，并且只能由对应项目经理本人导入。
- 导入按行使用数据库保存点：合法行成功入库，错误行保留 Excel 行号、字段和原因，最多保留 500 条错误明细。
- 导出工作簿包含筛选、冻结标题、列宽、日期格式和导出说明；日期/数字保留真实单元格类型。

## 风险与通知规则

- 风险扫描既可由风险中心手动触发，也可由 Celery Beat 每两小时执行。
- 同一业务风险使用稳定 `fingerprint` 去重；重复扫描刷新风险内容和检测时间，不重复创建。
- 风险状态为 `open → handling → resolved/ignored`，所有处理动作写入操作日志。
- 临期提醒每 30 分钟扫描一次；外部通知每 5 分钟尝试投递。
- 已确认预约每 5 分钟按北京时间自动推进为“进行中”或“已完成”，超过结束时间仍未确认的预约自动取消；打开共享看板或预约待办时也会即时补齐状态，避免未启动定时任务时页面长期显示旧状态。
- 通知偏好功能已移除；站内通知统一保存，提前提醒小时数和外部通知渠道由环境变量集中配置。
- 邮件与机器人配置缺失时不会影响站内信和核心业务事务。

## 用户账号、组织关系与删除规则

- 新增或导入用户时，`employee_no` 同时作为唯一登录账号，长度为 2–50，只允许可见的英文字母、数字和英文符号，不允许中文、空格或其他非 ASCII 字符；姓名不限制语言。
- 新增或导入用户必须设置有效部门和直属主管；最高级主管不在用户新增页面创建，由维护者直接写入数据库后再作为其他人员的主管。
- 用户使用内部自增数字 `id` 作为主键和业务外键。业务字段仅保留员工号/登录账号、姓名、邮箱、部门、组织、直属主管和系统角色；密码哈希、启停状态、软删除标记和时间戳属于系统运行字段。
- `users.department_id`、`organization_id`、`supervisor_id` 分别关联部门、组织和直属主管；用户不再包含手机号、兼容用户名、岗位、人事档案或人事职级。
- 系统角色固定为超级管理员、部门主管、职能主管、项目经理、项目成员，角色由本系统直接分配，不再记录人事职级自动授权来源。
- 不为新用户选择角色时，系统默认授予 `project_member`；清空最后一个角色时也会恢复该默认角色。
- 系统始终保留至少一个有效超级管理员；最后一个超级管理员不能被禁用、删除或移除角色。直属主管关系禁止形成循环，已停用部门、组织或主管不能继续分配给用户。
- 用户删除采用软删除：账号立即失效并从用户列表和选择项中隐藏，原员工号继续保留，项目、任务、工时和操作日志等历史数据不会丢失。
- 不能删除当前登录账号或最后一个有效超级管理员；用户仍负责活动项目、活动任务、活动排期或有效项目成员关系时，须先完成移交。
- 部门删除前必须先删除其全部组织节点，并完成部门下用户及项目的迁移；仍有关联用户或项目时后端会拒绝删除。
- 组织节点必须从叶子节点开始删除；删除后，相关用户变为未分配组织。
- 任务仅允许在“未开始”或“已取消”状态软删除；必须先处理子任务和活动预约，历史执行、评价和排期关联不会丢失。
- 升级到 `20260922_0015` 时，数据库中历史状态为 `Cancelled` 的项目会被物理删除；其项目成员、资源申请、任务、任务负责人、执行记录、评价、预约、风险及相关通知会按外键依赖顺序同步物理删除。该数据清理不可逆，执行迁移前必须先备份数据库。
- 项目页面当前仅允许删除尚未审批的草稿或已驳回项目；日常删除仍保留操作日志。排期的删除操作会转为 `cancelled`，任务、执行记录和通知等其他软删除数据继续保留供审计追溯，但不会出现在正常页面列表或报表统计中。
- 风险、评价、导入记录和操作日志属于业务或审计历史，不提供物理删除；风险通过处理、解决或忽略完成闭环。
